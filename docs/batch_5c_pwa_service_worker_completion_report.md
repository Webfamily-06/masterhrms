## 1. Executive Summary

In accordance with the bounded authorization for **Batch 5C**, MasterHRMS has implemented a dependency-free, security-hardened Service Worker (`public/sw.js`) and registered it conditionally in production within the document root (`src/routes/__root.tsx`).

### Core Guarantees Delivered
1. **Zero External Dependencies:** Built with native Web APIs without Workbox, `vite-plugin-pwa`, or build-time code injectors.
2. **Strict API & Private Data Bypass:** All `/api/*`, `/uploads/*`, and cross-origin requests bypass `CacheStorage` unconditionally. Network failures for APIs trigger standard browser network errors and are never served cached fallbacks.
3. **No Navigation Shell Caching (SSR Isolation):** Live SSR document navigations (`mode === 'navigate'`) are explicitly excluded from `CacheStorage` to prevent caching authenticated employee data, session tokens, or tenant-specific layouts.
4. **Verified Static Precache & Stale-While-Revalidate:** Only verified, physical static assets (`/manifest.webmanifest`, `/favicon.webp`, branding logos) and hashed production JavaScript/CSS bundles are cached.
5. **Production-Only Registration:** Service worker registration is gated by `import.meta.env.PROD` and browser capability detection, preventing interference during local development and testing.

## 3. Service Worker & Cache Architecture

### A. Lifecycle & Cache Management
- **Cache Name:** `masterhrms-static-v1`
- **Installation (`install` event):**
  - Opens `masterhrms-static-v1`.
  - Precaches verified physical assets from `PRECACHE_ASSETS`.
  - Invokes `self.skipWaiting()` to immediately activate the worker.
- **Activation (`activate` event):**
  - Iterates over all cache keys in `caches.keys()`.
  - Deletes obsolete caches matching the prefix `masterhrms-` while preserving unrelated caches.
  - Invokes `self.clients.claim()` to gain immediate control of active clients.

### B. Request Filtering & Fetch Policy

```text
Incoming Request
       │
       ▼
Is method === 'GET'? ──────────────► NO  ──► Direct Network (Bypass Cache)
       │ YES
       ▼
Is same-origin? ───────────────────► NO  ──► Direct Network (Bypass Cache)
       │ YES
       ▼
Path starts with /api/ or /uploads/? ──► YES ─► Direct Network (Bypass Cache)
       │ NO
       ▼
Is mode === 'navigate' (HTML/SSR)? ────► YES ─► Direct Network (Bypass Cache)
       │ NO
       ▼
Is precached asset OR (/assets|/ui-assets/ with static ext)?
       │ YES
       ▼
Serve from Cache (Stale-While-Revalidate with basic 200 validation)
```

### C. Cache Allowlist vs. Explicit Exclusions

| Asset Category | Target / Pattern | Strategy | Rationale |
| :--- | :--- | :--- | :--- |
| **PWA Manifest** | `/manifest.webmanifest` | Precache & SWR | Required for PWA installation and metadata. |
| **Favicons & Brand** | `/favicon.webp`, `/assets/img/*` | Precache & SWR | Static branding icons verified on disk. |
| **Hashed Bundles** | `/assets/*.js`, `/assets/*.css` | Stale-While-Revalidate | Immutable chunk hashes generated by Vite. |
| **API Endpoints** | `/api/*` | **Strict Bypass (Network-Only)** | Contains multi-tenant data, auth, payroll, and PII. |
| **Uploaded Documents**| `/uploads/*` | **Strict Bypass (Network-Only)** | Payslips, receipts, tax certificates, and confidential files. |
| **SSR Navigations** | `req.mode === 'navigate'` | **Strict Bypass (Network-Only)** | Dynamic TanStack Start SSR renders tenant/user state. |
| **Mutations** | `POST`, `PUT`, `DELETE`, `PATCH` | **Strict Bypass (Network-Only)** | Non-GET requests never touch CacheStorage. |
| **Cookie Responses** | Responses with `Set-Cookie` | **Strict Bypass (Never Cached)** | Prevents session hijacking and cache poisoning. |

## 4. Navigation Fallback Decision & Evidence

### Decision: Navigation Fallback is BYPASSED (No Offline HTML Shell)
- **Investigation:** MasterHRMS utilizes `@tanstack/react-start` server-side rendering (SSR). The root HTML payload dynamically renders server state, organization context, user entitlements, and authentication guards.
- **Security Assessment:** Caching the root `/` SSR document creates severe risks:
  1. **Tenant Bleed:** An employee in Tenant A could view Tenant B's navigation state or layout if cached without tenant isolation.
  2. **Stale Auth Shell:** A logged-out user could view cached authenticated navigation items.
  3. **False Availability:** Serving an offline shell for protected routes (`/hr/*`, `/me/*`, `/super/*`) creates a false impression that sensitive payroll or operational features are available offline.
- **Conclusion:** As authorized by Section 3.C of the specification, navigation fallback is deliberately **not implemented** in this batch. Unauthenticated, safe static shell architecture would require upstream router refactoring and must be evaluated separately.

## 5. Offline Queue Safety & Risk Audit

### Audit of `src/lib/web-apis/network-status.ts`
The existing implementation provides `OfflineQueueManager` and `useOfflineQueue` storing actions in `localStorage` (`hrms_offline_action_queue`).

### Identified Security Risks:
1. **Cross-Tenant Mutation Replay:** The queue does not encapsulate tenant ID, organization token, or user boundary. If User A (Tenant 1) submits actions while offline, logs out, and User B (Tenant 2) logs in, when the browser reconnects, the `online` event triggers `OfflineQueueManager.replayQueue()` using User B's active session.
2. **Missing Idempotency Controls:** Queued requests do not carry server idempotency keys. Network interruptions during replay can cause duplicate disbursements or record creation.
3. **No Statutory Protection:** Offline creation of attendance, leave, or expense claims lacks real-time validation against locked payroll months.

### Boundary Enforcement:
- As mandated by Section 3.E, the offline queue was **not modified or expanded** in Batch 5C.
- **Official Status:** The offline mutation workflow is **NOT PRODUCTION-SAFE**. Replay must remain disabled for sensitive operations until tenant-isolated queue gating is designed.

## 7. Known Limitations & Outstanding Security Risks

1. **No Offline App Shell for Protected Routes:** If network connectivity is lost, full page reloads on protected pages will display the browser's standard offline error rather than a custom offline dashboard.
2. **Offline Mutation Queue Vulnerability:** As detailed in Section 5, `hrms_offline_action_queue` in `localStorage` is not tenant-isolated and must not be used in multi-tenant production.
3. **Browser DevTools / Playwright E2E Limitation:** Browser DevTools Service Worker lifecycle simulation was conducted via local HTTP response inspection and code isolation; full headless browser PWA installation testing requires a dedicated staging HTTPS environment.
