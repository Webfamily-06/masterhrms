## 🛠️ 5. Technical Architecture & Endpoints

### Database Architecture
- **Schema Model:** `Addon` in `server/prisma/schema.prisma`
- **Tenant Entitlements:** `TenantAddon` table mapping tenants to enabled modular addons
- **Media / Icon Storage:** Uploaded directly to local encrypted storage at `/uploads/addons/icons/` and served via `POST /api/v1/media/upload`

### Management REST API Endpoints
- `GET /api/super/addons`: Fetch all marketplace extensions
- `GET /api/super/addons/categories?details=true`: Fetch categories with real-time add-on counts
- `POST /api/super/addons`: Create new modular add-on extension
- `PUT /api/super/addons/:id`: Update add-on details, pricing, icon, or status
- `DELETE /api/super/addons/:id`: Archive or delete add-on
- `POST /api/super/addons/sync-canonical`: Idempotent sync of the canonical 133 WorkDo reference catalog
- `POST /api/v1/media/upload`: Multipart image/icon upload directly to system storage

### Frontend Surfaces
- **Next.js CMS Explorer:** [CMS Marketplace URL](http://localhost:3000/super/marketplace)
- **TanStack Router Console:** `src/routes/_authenticated/super/marketplace.tsx`
